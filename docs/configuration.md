# Configuration

Pass a JSON file with `--config FILE`. Unknown fields, wrong types and values
outside their documented ranges are rejected at startup. Relative paths in the
file are resolved from the file's directory. Command-line values override the
file even when `--config` appears later on the command line.

```json
{
  "stateDir": "./state",
  "listen": { "address": "127.0.0.1", "port": 9080 },
  "web": {
    "enabled": true,
    "publicDir": "./public",
    "backgroundWorkers": 2,
    "maxConnections": 128,
    "ioTimeoutMs": 30000,
    "maxBodyBytes": 65536,
    "maxUploadBytes": 67108864,
    "maxStaticFileBytes": 4194304
  },
  "status": {
    "enabled": true,
    "intervalMs": 30000,
    "timeoutMs": 5000
  },
  "calls": { "defaultTimeoutMs": 30000 },
  "runtimeStartTimeoutMs": 10000,
  "events": { "enabled": true, "capacity": 256 },
  "auth": {
    "enabled": false,
    "username": "admin",
    "passwordHash": "",
    "sessionIdleTimeoutMs": 1800000,
    "sessionMaxLifetimeMs": 86400000,
    "maxSessions": 64,
    "secureCookie": false
  },
  "endpoints": {
    "enabled": true,
    "maxSessions": 128,
    "maxSessionsPerPackage": 32,
    "maxRequestBodyBytes": 1048576,
    "maxResponseBodyBytes": 4194304,
    "maxMessageBytes": 262144,
    "maxQueuedMessages": 64,
    "maxQueuedBytes": 1048576,
    "idleTimeoutMs": 60000,
    "maxLifetimeMs": 86400000
  }
}
```

## Fields and limits

| Field | Default | Accepted values |
| --- | ---: | --- |
| `stateDir` | `/var/lib/circud` | non-empty path |
| `listen.address` | `127.0.0.1` | numeric IPv4 or IPv6 address |
| `listen.port` | `9080` | `1..65535` |
| `web.enabled` | `true` | boolean |
| `web.publicDir` | discovered install/source directory | non-empty path; with `--check-config`, an existing directory when Web is enabled |
| `web.backgroundWorkers` | `2` | `1..16` |
| `web.maxConnections` | `128` | `1..4096` |
| `web.ioTimeoutMs` | `30000` | `100..300000` |
| `web.maxBodyBytes` | `65536` | `1024..65536` |
| `web.maxUploadBytes` | `67108864` | `1024..67108864` |
| `web.maxStaticFileBytes` | `4194304` | `1024..67108864` |
| `status.enabled` | `true` | boolean |
| `status.intervalMs` | `30000` | `1000..3600000` |
| `status.timeoutMs` | `5000` | `100..300000` |
| `calls.defaultTimeoutMs` | `30000` | `1..300000` |
| `runtimeStartTimeoutMs` | `10000` | `100..300000`; bounds package runtime startup before the generation is fenced off |
| `events.enabled` | `true` | boolean |
| `events.capacity` | `256` | `32..4096` |
| `auth.enabled` | `false` | boolean; requires a non-empty valid `passwordHash` when enabled |
| `auth.username` | `admin` | non-empty string, at most 128 bytes |
| `auth.passwordHash` | empty | scrypt hash generated by `circud hash-password` |
| `auth.sessionIdleTimeoutMs` | `1800000` | `1000..86400000`, not greater than max lifetime |
| `auth.sessionMaxLifetimeMs` | `86400000` | `1000..2592000000` |
| `auth.maxSessions` | `64` | `1..4096` |
| `auth.secureCookie` | `false` | boolean; enable when the direct connection uses HTTPS |
| `endpoints.enabled` | `true` | boolean |
| `endpoints.maxSessions` | `128` | `1..4096` |
| `endpoints.maxSessionsPerPackage` | `32` | `1..1024`, not greater than `maxSessions` |
| `endpoints.maxRequestBodyBytes` | `1048576` | `1024..16777216` |
| `endpoints.maxResponseBodyBytes` | `4194304` | `1024..67108864` |
| `endpoints.maxMessageBytes` | `262144` | `1024..4194304`, not greater than `maxQueuedBytes` |
| `endpoints.maxQueuedMessages` | `64` | `1..1024` |
| `endpoints.maxQueuedBytes` | `1048576` | `1024..67108864` |
| `endpoints.idleTimeoutMs` | `60000` | `1000..3600000`, not greater than `maxLifetimeMs` |
| `endpoints.maxLifetimeMs` | `86400000` | `1000..604800000` |

The normal HTTP body limit cannot exceed the fixed 64 KiB JSON call-envelope
limit. ZIP uploads use their separate limit and are streamed in bounded 64 KiB
chunks to a temporary file under `stateDir/uploads`; they are not retained
after the request. Public and package-delegated static files are likewise read
in one bounded chunk at a time. Socket I/O stays on the main network/control
loop, while disk reads, disk writes, ZIP validation and installation run on the
bounded `web.backgroundWorkers` generation. A full background queue applies
backpressure instead of buffering another file. Stale upload files from an
abnormal daemon exit are removed on the next HTTP server start.

`web.backgroundWorkers` is not a pool of per-connection HTTP workers. Listener
stop closes admission and connections without joining a stuck disk operation;
a later start creates an independent listener/background generation.
`web.maxConnections` bounds all accepted connections, and each short-lived
connection also has the configured read/write deadline.

`endpoints` bounds package-owned HTTP, SSE and WebSocket sessions separately
from management requests. Session counts are enforced globally and per package;
the body, message and outbound queue limits prevent a package or slow peer from
causing unbounded buffering. Idle sessions and all long-lived sessions are
closed at their configured deadlines. Setting `endpoints.enabled` to `false`
disables all package scopes without disabling the management UI. Every
installed package owns `/<package-id>` by default; a manifest `prefix` replaces
that scope. Requests in the scope are delivered to the package, and files are
served only when its handler explicitly calls `event.serveStatic()`.

The former `web.workers`, `web.queueLimit`, `--http-workers` and
`--http-queue-limit` settings are intentionally rejected. Replace them with
`web.backgroundWorkers`, `web.maxConnections`,
`--http-background-workers` and `--http-max-connections` respectively.

Management events use a thread-safe in-memory ring buffer. `events.capacity`
bounds its retained entry count; events are intentionally not written to disk
and are reset whenever the daemon process restarts. Event payloads contain
fixed operational summaries rather than RPC arguments, return values,
environment values, filesystem paths or archive contents.

Use `--check-config` in service validation and `--print-config` when debugging
overrides. `--print-config` deliberately replaces a configured password hash
with `<redacted>`; its output is a safe diagnostic view, not a configuration
backup that can be fed back to circud while authentication is enabled. In
addition to syntax and value checks, `--check-config` verifies
that `web.publicDir` exists as a directory whenever Web serving is enabled.
`--help` lists every command-line equivalent. IPv6 listen arguments use bracket
notation, for example `--listen '[::1]:9080'`.

Authentication gates the management RPC and ZIP-install routes when enabled;
static Web assets stay public, and package endpoints receive only the advisory
session state. Generate the password hash interactively with
`circud hash-password`. Keep the default loopback address, or place an
authenticating reverse proxy in front before exposing the listener.

## OpenWrt and LuCI

The OpenWrt package starts circud with
`--config /etc/circud/config.json`. The packaged configuration uses absolute
paths for `/var/lib/circud` and `/usr/share/circud/public`, and package upgrades
preserve local edits.

The optional `luci-app-circud` package manages only the daemon and this JSON
file. Its tabbed form covers every supported configuration field, including
secure password-hash generation through circud's own TTY-only command. It
validates candidate content with `circud --check-config` before an atomic
same-directory replacement. “Save” does not alter the running process; “Save &
Apply” restarts circud after a successful save. Package installation,
per-package lifecycle, calls and status refresh remain owned by circud's Web
management interface, which LuCI exposes through its authenticated session.
LuCI accounts with read-only access can inspect the daemon configuration but
receive `<redacted>` instead of the configured authentication hash; only the
write ACL may request the complete value needed to preserve or replace it.
The proxy never accepts a client-selected target and never forwards the LuCI
cookie to circud. If circud authentication is enabled, the proxy accepts only
the fixed-format circud session token from its own path-limited
`luci_circud_session` cookie, maps it to `circud_session` upstream, and forwards
only a validated `X-Circud-CSRF` value. Other upstream cookies are discarded.
It is limited to `/`, `/index.html`, `/app.js`, `/app.css`,
`/circud-api.d.ts`, `/favicon.ico`, `/assets` and its descendants, `/health`,
`/rpc`, `/api/auth/session`, `/api/auth/login`, `/api/auth/logout`, and
`/api/packages/install`; unknown or future `/api` routes and package prefixes
are rejected. This LuCI compatibility path uses buffered HTTP/1.0 and only
`GET`, `HEAD`, and `POST`, so package HTTP methods, SSE, and WebSocket must use
circud's native listener. Upgrade and `text/event-stream` requests are rejected
explicitly.
